# euipo-api-portal — service facts

euipo-api-portal — a local, production-like copy of the EUIPO developer portal (https://dev.euipo.europa.eu). Code: `.` (the repository root — in-repo). The Drupal root `site/` is generated by `./build-local-site.sh` from the IBM sources (ddev `docroot: site`); our code is in `eap/`, bind-mounted into `site/sites/default/{modules,themes}/custom`.

Stack: IBM API Developer Portal 10.0.8.12 (production runs 10.0.8.11) · Drupal 11 · PHP 8.4 (ddev) · Keycloak as the EUIPO identity provider and `mock-apic` as IBM API Connect, locally · MkDocs docs in `eap/docs/` (served at :8800).

## Modules

5 custom modules in `eap/modules/` (`eap_apim_customs`, `eap_api_status`, `eap_credentials_sync`, `eap_redoc`, `eap_deployer`) and the sub-theme `eap/themes/eap_theme` (of IBM `connect_theme`; `css/` is generated). One card per module: `.ai/context/modules/`. Integrations: `.ai/integrations.md`.

## Commands (beyond the gate)

```bash
ddev start                                   # web, db, keycloak, mock-apic, docs
./build-local-site.sh                        # rebuild site/ from the IBM sources (no database change)
ddev install-portal [production|sandbox]     # full reinstall — DROPS the database
ddev seed-portal [env] [steps]               # re-apply the seed (steps: config,settings,catalog,content,eap)
ddev eap-theme-css                           # compile the eap_theme CSS
ddev drush cache:rebuild | pm:install <module> | updatedb
eap/scripts/build.sh                         # package modules and theme as .tar.gz in eap/build/
```

Run `ddev drush cache:rebuild` after PHP, YAML or Twig changes and `ddev eap-theme-css` after SCSS changes. Full reference: `eap/docs/dev-documentation/01-setup.md`.

The gate of this service is the one in the services table of `.ai/orchestrator.md`. Stack rules: `.ai/rules/stacks/drupal.md` — read with this file. Tools run in: ddev — `.ai/project.json`. phpcs and phpstan are not set up: the repository root has no `composer.json` and the one in `site/` is regenerated by `./build-local-site.sh`, so the gate reports them as missing.

## Conventions

The conventions common to every service are in `.ai/orchestrator.md` (IBM code never edited, packages only, no `hook_update_N`, settings forms, camelCase variables, no `else`, English comments, no AI credit in git).

### Specific restrictions of this service
- Everything an operator must set is a settings form, and its per-environment values are documented in `eap/docs/`.
- Anything that must exist after an install or upgrade is idempotent and re-runnable from a button (never only `hook_install` / `hook_update_N`).
- Titles of our routes and menu links start with "EAP", and every admin page has a route and a menu link.
- No new Composer or npm dependency at runtime: assets are bundled inside the module (e.g. `eap_redoc/js/redoc.standalone.js`).
- Bump `version:` in `*.info.yml`, run `eap/scripts/build.sh`, commit `eap/build/*.tar.gz`, update `eap/docs/` and the skill, verify on the test portal before sandbox and production.

### Known Gotchas
- `apic_app_pre_delete` is invoked with string keys, so PHP passes them as named arguments: the parameters must be named exactly `$node` and `$data` (`.ai/skills/01-credentials-sync.md`).
- The same version number does not mean the same code: download the portal's **stable** package (`eap_deployer`) and diff it against git before deploying (the dummy portal ran a divergent `eap_credentials_sync` 1.0.0) — `.ai/skills/05-deployer.md`.
- Deploying locally with `eap_deployer` rewrites the files in the repository (bind mount), and `ddev install-portal` does not enable `eap_deployer`: `ddev drush pm:install eap_deployer`.
- After an IBM upgrade, check that the swapped IBM services still have the same methods: `ApplicationService::createOrUpdate()`, `ConsumerOrgService::createNode()` / `createOrUpdateNode()` (`.ai/skills/03-apim-customs.md`).
- `./build-local-site.sh` reports 2 unapplied IBM patches: expected.
